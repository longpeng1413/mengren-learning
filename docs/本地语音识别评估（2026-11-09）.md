# 本地语音识别评估（2026-11-09）

用户问：能不能把猛人输入法的本地语音识别加进猛人学习？本地识别能不能用专用术语表？

## 方案来源

- 猛人输入法 `crates/qingjian-voice-offline`、猛人快传 `app/lib/src/voice/speech_service.dart`：**sherpa-onnx**（k2-fsa，Apache-2.0）+ **SenseVoice Small int8**（FunAudioLLM，2024-07-17 官方原版，k2-fsa 转换；2025-09-09 那版是粤语模型转的，普通话漏字多，不用）。
- 模型两个文件：`model.int8.onnx`（239,233,841 字节，SHA-256 `c71f0ce0…2cd51`）、`tokens.txt`（315,894 字节，`f449eb28…1dc`），猛人快传放在 GitHub `longpeng1413/mengren-kuaichuan` 的 Release `asr-model-sensevoice-2024-07-17` 上，下载后核对。这台电脑上猛人快传已经下好一份：`%APPDATA%\com.personal.lantransfer\lan_transfer\asr_model\sensevoice-int8-2024-07-17\`。
- 长录音的切法（猛人输入法）：每段不超过 20 秒，超过时在第 10～20 秒里最安静的 0.1 秒处切开；打开逆文本规整（数字、标点）。
- Python 版 `sherpa-onnx` 2.0.1（PyPI，约 28 MB，自带 onnxruntime），和两个项目用的版本相同。

## 术语表能不能用

- **SenseVoice 不能用热词。** sherpa-onnx 的热词（contextual biasing）只支持 transducer 类模型（要用 modified_beam_search 解码），官方文档写明其他模型都不支持；SenseVoice 不是 transducer。
- 术语表照样能起作用的地方：
  1. 识别后的「直接替换」（`=>!`）：现在那 13 条是照豆包的错法写的，对本地识别几乎没用（6.8% → 6.8%）。可以按本地识别的错法另写，但「分级」「风景」这类词直接替换容易误伤，不建议多写。
  2. **AI 校对**（带术语表）：实测把「峰 / 级」的错全部改对了（见下），这是主要的办法。
- 能读热词的本地模型：FunASR 的 SeACo-Paraformer 支持热词（funasr-onnx 0.4.7 有对应的运行代码），但它的时间戳在 ONNX 下官方没验证过，模型也更大；这次没有测。

## 实测：《1、峰级线基础画法》（18 分 14 秒）

标准答案是人工校对后的终稿（4387 字，不算标点；「峰」「级」共 192 个）。**这份终稿是在豆包原稿基础上人工改出来的，听不出差别的地方偏向豆包的写法**，对本地识别不完全公平。

| 来源 | 错字率 | 峰 / 级认错 | Terra 整节课校对后错字 | 校对后峰 / 级认错 |
|---|---|---|---|---|
| 豆包极速版（当初的识别原稿，带术语热词） | 3.0%（131 个） | 101 | 0.3%（15 个） | 0 |
| 本地 SenseVoice | 6.8%（300 个） | 169 | 2.0%（89 个） | 0 |

- 速度：模型加载 1 秒，识别 23 秒（4 个线程，约 47 倍速），不联网、不花钱。
- 断句：184 句，平均 26 字、最长 79 字；人工终稿 180 句、平均 27 字、最长 90 字，几乎一样，时间也准（例如第一句 0.06 秒对 0.16 秒）。缺点：20 秒切段的地方会被加上句号，把一句话切成两半（例如「它一定是分。」「之后连接着极……」），要改进（按停顿长短切、或者切段处的半句接回去）。
- 校对后本地识别剩下的 89 个差别：18 个是「呃」（本地识别照写，校对规则不删口语）；不少是写法（「123」对「一二三」、「3 根」对「三根」，可以关掉阿拉伯数字；「的 / 地 / 得」）；几处「比如说」「也就是说」互换（标准答案偏向豆包）；真正改了意思的只有少数，例如「急上急下」被改成「极上极下」。
- 结论：**本地识别 + AI 校对可以用，但比豆包 + AI 校对粗**，人工校对要多花一些工夫；交易课这种术语多的课，差距主要在术语，AI 校对能补回来大半。

## 补充测试：能用热词的 SeACo-Paraformer，三节课（同一天，用户要求）

- 模型：FunASR 的 SeACo-Paraformer（`iic/speech_seaco_paraformer_large_asr_nat-zh-cn-16k-common-vocab8404-pytorch`）+ fsmn-vad 切段 + ct-punc 中文标点，`sentence_timestamp=True`。官方只发布 PyTorch 版（网上的 ONNX 是第三方转的，热词用法官方没验证过），所以用 PyTorch 测：运行环境 1.5 GB（PyTorch CPU 版 + FunASR 1.4.24），三个模型 1.3 GB。热词按空格分隔交给 `hotword`。
- 三节课：《1、峰级线基础画法》（18 分钟，已校对）、《峰级分析》10.22 答疑（61 分钟，已校对，有「AI 校对前」原稿，豆包录音文件识别 1.0）、「3、实战技术《峰级战法》」的《1、交易底层逻辑》（25 分钟，**没有人工校对**，只能数术语）。三节用的都是「咖米峰级分析」那份术语表（118 个热词）。

| | 18 分钟：错字率 / 峰级认错（共 192） | 61 分钟答疑：错字率 / 峰级认错（共 292） | 25 分钟（未校对）：认出的多字术语次数 |
|---|---|---|---|
| 豆包（原识别稿，带热词） | 3.0% / 101 | 2.3% / 20 | 70 |
| SenseVoice | 6.8% / 169 | 7.3% / 275 | 5 |
| SeACo 不带热词 | 6.6% / 158 | 6.7% / 221 | 3 |
| SeACo 带全部 118 个热词 | 5.8% / 122 | 5.9% / 124 | 59 |
| **SeACo 只带多字热词**（本地最好） | 5.6% / 116 | 5.9% / 116 | 60 |
| SeACo 只带前 30 个热词 | 5.7% / 119 | 6.0% / 119 | 58 |
| **豆包 + Terra 校对** | **0.3% / 0** | **1.9% / 3** | — |
| SenseVoice + Terra 校对 | 2.1% / 1 | 4.4% / 5 | — |
| SeACo 只带多字热词 + Terra 校对 | 2.6% / 5 | 4.7% / 3 | — |

- 速度（4 线程 CPU）：SenseVoice 18 分钟 24 秒、61 分钟 88 秒；SeACo 39 秒、136 秒。SeACo 第一次加载模型要 100 秒（之后 5 秒）。
- 热词有用：SeACo 认出的术语多得多（25 分钟那节 60 次对 SenseVoice 的 5 次），「峰 / 级」认错少了三到六成；单字热词（「峰」「级」）基本不起作用，热词全给和只给前 30 个差不多。
- **但经过 AI 校对以后，SeACo 不比 SenseVoice 好**（2.6% 对 2.1%、4.7% 对 4.4%）：术语本来就能靠 AI 校对改回来，术语以外的普通字词 SeACo 错得还多一点。
- 断句：SeACo 在逗号处就分句，按句号合并后平均 37～39 字一句，比人工稿（25～28 字）长；SenseVoice 和人工稿差不多。
- 两种本地识别经 AI 校对后都**明显不如豆包 + AI 校对**，长的答疑课差距更大（4.4% 对 1.9%），要人工校对的地方多一倍以上。
- 10.22 视频结尾有损坏，核对过抽出来的音频是完整的 3685 秒，比较公平。

**结论：本地识别选 SenseVoice，不用 SeACo。** 最终效果差不多，SenseVoice 小得多（引擎 28 MB、模型 240 MB，电脑上猛人快传已经有一份），SeACo 要带 PyTorch（打包后软件会大 1 GB 以上）加 1.3 GB 模型。SeACo 只在「不做 AI 校对、又要术语认得多」时才有优势，猛人学习的流程本来就有 AI 校对。

## 补充测试：术语少的课（人间落叶《野生小散成为职业交易员的路径和方法-下》，22 分钟）

- 用户要求换一节术语少的课再测。这节标着「已人工校对」，但只改过 4 处（两处加批注、一处删空格、一处去掉重复的字），**终稿基本就是豆包录音文件识别 1.0 的原样**，不能当公正的标准答案，所以改成：本地识别和豆包原稿逐处比较，按上下文判断谁对（没有听原音，个别拿不准）。术语表档案「人间落叶」只有 30 个词，多是英文缩写。
- SenseVoice：识别 27.6 秒；222 句、平均 27 字（豆包 246 句）。和豆包不同的字占 3.5%（峰级几节是 6%～7%），137 处里：
  - 本地明显错的约 45 处（「设计交易系统」→「数据教育系统」、「去伪求真」→「趣尾求真」、「苏炳添」→「宿炳天」、「拳打万遍，其义自现」→「拳打万变奇异自信」、术语「熔炼」→「容链」、「滑点」→「划点」、「理念」→「里面」、「覆盖」→「不该」等）；
  - 豆包错、本地对的 3～4 处（结尾「日进斗金」豆包写成「进抖金」等）；
  - 写法不同约 60 处（「这事儿」的儿、他 / 它、的 / 地 / 得、数字「5」、语气词）；其余是多一两个、少一两个口头字。
- 两边各做一次 Terra 整节校对后：AI 改了豆包 21 句、本地 46 句；剩下不同的字 2.4%，**绝大多数是写法不同**，本地真正还错着的只剩 6～8 处（「震荡」→「真的」、「小资金」→「小鸡金」、「水电煤气」→「水电煤及」、「三五年」→「三几年」等）。
- 结论：**术语少的课，本地识别 + AI 校对和豆包 + AI 校对已经很接近**，人工校对时多改几处就行；术语多的课（峰级）差距大得多。

## 建议

1. **加进猛人学习，作为一个识别选项，不当默认**：「生成字幕」「一键整理」对话框、文件夹整理规则、设置里的识别方式都能选「本机（免费）」；命令行 `--model local`（现在返回 `not_supported`）接上。
2. 适合：灵修这类音频课（术语少、数量大，省豆包的钱）、豆包额度用完或欠费时、没网时。术语多的交易课继续用豆包流式 2.0。
3. 本地识别出来的字幕**一定要接 AI 校对**（一键整理本来就有）。
4. 要做的事：
   - `asr.py` 加本地识别：按停顿切段、识别、按标点和每个字的时间切句、时间戳；进度、可以取消；用完释放内存。
   - 模型下载：先找猛人快传已经下好的那份（核对 SHA-256 后直接用，不重复下载），没有再从猛人快传的 GitHub Release 下载（显示进度、可以停、断点续传、核对），放在软件自己的「模型」文件夹，设置里显示占多大、能删除；半截下载 7 天后清掉。
   - 打包：`sherpa-onnx` 加进依赖和 PyInstaller（Windows 11 的 System32 里有一个旧的 onnxruntime.dll，猛人快传专门处理过，要实测打包版加载的是自己带的那份）；程序变大约 30 MB，模型不随包。
   - 切段处断句改进；数字写法跟着设置（默认写汉字，和人工稿一致）。
   - 测试：后台测试用一小段测试音频跑本地识别（模型不在时跳过），界面测试加选项。
5. 模型许可：sherpa-onnx 是 Apache-2.0；SenseVoice 是 FunASR 模型许可，发布说明里要写明来源。
