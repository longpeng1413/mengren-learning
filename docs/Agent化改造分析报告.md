# 猛人学习软件 Agent 化改造分析报告

2026-10-14 · 基于 1.7.13（本机已加「单句循环」修正，未发布）代码的完整检查 · **本报告只做分析，没有改任何代码**

---

## 0. 一句话结论

**能做，而且底层大部分能直接复用。** 但当前有一个关键问题必须先解决：**「把 AI 结果合进字幕文件」这一层写在界面的 JavaScript 里**，不在后台。所以不能直接给后台加命令行就完事，否则 Agent 那边就得把这些规则再写一遍，正是你禁止的「两套逻辑」。

正确顺序是：先把这一层从界面挪到后台，做成统一的「任务层」；界面和命令行都调它。这一步要动现在稳定的界面流程，必须分步做、每步跑全部回归测试。

另外，你的需求里有 **6 处和你以前定下的规则冲突，或软件目前做不到**（见第 9 节），需要你先拍板。

## 1. 当前架构

```
界面（app/web：index.html + app.js 2155 行，纯 JS，无框架）
   │  window.pywebview.api.call(名称, 参数)          ← 不走网络端口（360 / Clash 会干扰本机回环）
   ▼
桥（app/bridge.py：Api.call → do_xxx，约 50 个入口，统一捕获错误返回 {ok, error}）
   │
   ▼
核心模块（app/core）
   ├─ media.py     ffmpeg：探测、转码、抽音频、按静音切段、检查结尾损坏
   ├─ asr.py       识别：豆包（极速 / 流式 / 标准 / 闲时）、OpenAI Whisper、硅基流动
   ├─ llm.py       AI 调用（7 家）、校对、翻译、课程重点提示词、查漏补缺、找新术语、术语表解析
   ├─ frames.py    关键帧：候选 → AI 筛选 → 写说明 → 去重；画面复核存疑句
   ├─ doc.py       字幕文件（视频旁的 .猛人学习.json）读写、导出、Markdown、剪藏合并
   ├─ glossary.py  把确认过的新术语写进 Obsidian 术语表（先备份）
   ├─ library.py   媒体库扫描和状态
   ├─ config.py    设置、老师档案、媒体库、播放进度（%APPDATA%\猛人学习）
   ├─ jobs.py      后台任务（只在内存里）
   └─ log.py       日志（2MB × 4 份轮换）
```

**数据**：
- 每节课一个 `视频名.mp4.猛人学习.json`，在视频旁边。字段：`segments`、`summary`、`frames`、`doubts`、`fixes`、`versions`、`terms_pending`、`clip` 等。
- 媒体库在 `%APPDATA%\猛人学习\library.json`，只记文件夹路径。课程 = 文件夹，视频 = 扫描出来的文件。**没有 course_id / video_id**，靠文件路径识别。

## 2. 界面和业务逻辑的耦合程度

| 层 | 现状 | 能否被 Agent 直接用 |
|---|---|---|
| 核心算法（识别、AI 调用、找关键帧、查漏、术语、Markdown、剪藏合并） | 都在 Python 后台，函数接收「设置 + 回调」，不依赖界面 | **能**，直接复用 |
| 「把结果合进字幕文件」的规则 | **在 app.js 里** | **不能**，必须挪到后台 |
| 一键整理的步骤编排 | **在 app.js 的 `runPipeline()`** 里 | **不能**，必须挪到后台 |
| 当前这节课的数据 | 界面在内存里拿着整份 doc，自动保存时整份写回 | 和 Agent 同时改同一节课会互相覆盖 |

写在 app.js 里、Agent 需要但拿不到的规则（**这些就是要挪的东西**）：
- 识别：重新识别前存历史版本（最多 5 份）、清掉「已校对」、记录识别服务和模型、豆包闲时任务的 `pending_task` 记录；
- AI 校对：逐句替换、把每处改动记进 `fixes`（积累术语表要用）、存疑句按开始时间记进 `doubts`、标记 `corrected`；
- 找关键帧：保留手动截取的、替换自动挑的、排序；
- 画面复核：改正的记进 `fixes`、确认的去掉存疑标记；
- 课程重点：保存后自动查漏补缺（查漏失败不影响重点本身）；
- 新术语：结果存进 `terms_pending`，等人勾选；
- 剪藏：冲突时先问、确认后备份覆盖，记录 `clip`；
- 一键整理：步骤顺序（你定的：校对 → 关键帧 → 复核存疑 → 课程重点 → 剪藏 → 新术语）、哪步失败就停、复核失败不影响后面。

## 3. 可以直接复用的

`media.*`、`asr.recognise`（包括豆包闲时任务的断点续取）、`llm.correct_all / summary_messages / stream / review_summary / suggest_terms / coverage / parse_terms / terms_from_markdown`、`frames.extract / recheck_doubts / grab`、`doc.load / save / to_markdown / clip / merge_note / place_figures / export`、`glossary.add`、`library.scan / _status`、`config.*`。

这部分是质量的核心（提示词、查漏、剪藏合并、术语表格式），**一行都不需要重写**。

## 4. 需要拆分的

1. **「合进字幕文件」规则**：从 app.js 挪到新的后台任务层，以 Python 为准；界面改成「调用任务 → 完成后重新读字幕文件 → 刷新显示」。
2. **一键整理编排**：从 `runPipeline()` 挪到后台。界面只负责勾选和显示进度。
3. **bridge 的入口**：现在很多入口收的是界面传来的整份 doc（`b.get('doc')`）。改成按文件路径从磁盘读，界面传来的只当作「未保存的修改」先保存。
4. **任务状态**：`jobs.py` 只在内存里，软件一关就没了，没有阶段、重试次数、错误分类。

## 5. Agent 接口放在哪一层

```
界面（GUI）           命令行（CLI，本期）      MCP（以后，stdio，不开端口）
     │                       │                        │
     └──────────┬────────────┴────────────────────────┘
                ▼
     任务层 app/core/workflow.py   ← 唯一的业务入口：找视频、识别、校对、关键帧、复核、
                │                     课程重点、术语、Markdown、剪藏、整条流水线
                ▼                     （负责读写字幕文件、加锁、记任务状态、重试）
     核心模块（现有，不动）
```

**接口放在「任务层」**：界面的 `bridge.do_xxx` 和命令行的 `mengren xxx` 都只是薄薄一层，参数转换后调同一个 `workflow.xxx()`。以后加 MCP 也只是再加一个薄入口。

**以后的 API 不建议用本机 HTTP 端口**：维护说明里记着，你电脑上的 360 和 Clash 会干扰本机回环连接，以前出过界面卡死。MCP 用 stdio（标准输入输出）方式，不开端口，正好避开。

## 6. 需要新增的模块

| 模块 | 作用 | 估计 |
|---|---|---|
| `app/core/workflow.py` | 任务层：每个能力一个函数，读盘 → 调核心 → 按规则合并 → 加锁保存 → 返回结构化结果 | 500～700 行 |
| `app/core/tasks.py` | 持久化任务记录（`%APPDATA%\猛人学习\tasks\<task_id>.json`）：pending / running / completed / failed / cancelled，每个阶段独立状态、开始和结束时间、错误码、能否重试、重试次数、用的模型和参数、输出文件 | 约 250 行 |
| `app/core/errors.py` | 统一错误码：网络超时、接口临时错误（可重试）；文件不存在、缺密钥、配置错误、视频损坏（不重试） | 约 80 行 |
| `app/cli.py` | 命令行，全部支持 `--json` | 约 300 行 |
| 打包 | 另出一个**控制台版** `mengren.exe`，放在同一个软件文件夹。现在的 `猛人学习.exe` 是窗口程序，打不出命令行输出 | 改 build.py |
| `video_id` | 用「文件路径的规范化指纹」（同一文件永远同一个 id），不另建数据库；`course_id` 同理用文件夹 | 在 library.py 里 |
| 任务日志 | 每个任务的完整过程写进任务记录，再在总日志里记一行。密钥字段一律不写（现有 `config.SECRETS` 打码机制复用） | 在 tasks.py |

## 7. 风险

1. **（最高）界面和 Agent 同时改同一节课。** 现在保存是「后写的覆盖先写的」，没有冲突检查。比如你开着这节课在看，Agent 在后台校对完写进去；你的界面一自动保存，就把 Agent 的结果冲掉了，反过来也一样。**对策**：
   - 每个字幕文件加锁；
   - 保存时核对「我读到的版本号」，不一致就不覆盖，界面提示「这节课在后台被更新了」并重新读取；
   - Agent 默认不处理你正打开、且有未保存修改的那节课。
2. **（高）从 Claude 桌面版里启动的程序，写 %APPDATA% 会被转存到私有文件夹**，2026-10-11 刚出过事。在 Claude 桌面版里调用命令行时，命令行读到的可能是空设置、没有密钥，写下的任务记录也会进私有文件夹。**对策**：命令行启动时用现成的 `appdata.is_virtualized()` 检测；发现被转存就拒绝运行，并给出明确的结构化错误。Codex、终端里的 Claude Code 不受影响。
3. **（高）把界面流程挪到后台，可能改坏现在稳定的功能。** 对策：一步一步挪；每挪一步，都先把现有界面测试（107 项）和后台测试（223 项）跑全，再补这一步的新测试。行为以「挪之前的效果」为准，不顺手改提示词、不改笔记结构。
4. **（中）字幕文件有自动备份，但只留一份 .bak。** Agent 批量跑时，一次跑错可能覆盖好结果。对策：Agent 每一步改字幕前存一份历史版本（复用现有 `versions`，最多 5 份），并且只在你明确要求时才重跑已完成的步骤（`force`）。
5. **（中）调用量和费用。** 「把今天新增的全部整理」可能一次跑几十节课。对策：
   - 已完成的步骤不重复跑；
   - 批量任务默认一次只跑一节；
   - 结果报告里列出每节课用了哪个模型、调用了几次。
6. **（低）坏视频。** 这次抽查发现两个视频只下载了一半。对策：现有的 `media.tail_problem` 已能发现，任务层把它变成「视频损坏，不重试」的明确错误。

## 9. 需要你先拍板的地方（和你以前的决定冲突，或目前做不到）

1. **「本地模型识别」目前没有。** 软件现在的识别服务全是云端：豆包、OpenAI Whisper、硅基流动。以前本地模型生成的 .srt，你决定过不用。要支持 `model="local"`，得另加一个本地识别引擎（比如 faster-whisper，要下载几个 GB 的模型，CPU 跑得慢）。**建议**：本期只做「云端」，接口留好 `model` 参数，以后要本地再加。
2. **「重点提炼」的固定结构**（核心观点 / 交易逻辑 / 方法论 / 操作规则 / 风险提示 / 案例 / 值得进知识库）**和你 2026-10 定的规则冲突**：课程重点「不设固定模板，按老师这节课实际的知识体系组织，只写老师讲过的」。**建议**：
   - 课程重点保持现在的写法不变，Agent 调用得到的是同一份；
   - 如果你需要给 Agent 用的结构化信息，另加一个**只给程序看**的结构化摘要字段（JSON，不进笔记），从课程重点里抽，不额外编内容。

   要不要这个摘要字段，由你决定。
3. **Markdown 模板可配置 vs 笔记结构稳定。** 现在的笔记是：属性 → `## 课程重点` → `## 完整字幕`。重新剪藏时的「合并、保留你加的内容」就靠这几个小节名，你也说过结构要稳定、方便以后蒸馏。**建议**：模板做成可配置，但默认模板和现在一字不差；以后你给正式模板时，软件负责的小节名不能随便改，改了要同时迁移旧笔记。
4. **一键整理的步骤。** 你需求里的流水线是「识别 → 校对 → 重点 → 术语 → Markdown」，少了你之前定的「找关键帧」和「用画面复核存疑句」（顺序：校对 → 关键帧 → 复核存疑 → 课程重点 → 剪藏 → 新术语）。**建议**：Agent 的默认流水线和界面的一键整理完全一样。
5. **「待审核区」放在哪里。** 按你知识库的规则，`03、收集箱` 本来就是「还没放行」的区域：剪藏进去的笔记要你打开「人工校对」才算放行，正式知识库是 `05`。**建议**：
   - Agent 默认只生成 Markdown 草稿，放在软件自己的输出文件夹，不剪藏进 Obsidian；
   - 加 `--clip` 参数时才剪藏进 `03、收集箱`，而且永远不会把「人工校对」设成 true；
   - 新术语只进 `terms_pending`（待勾选），永远不直接写术语表（现在界面也是这样）。
6. **术语分类。** 现在找新术语时只分「新术语」和「识别错误」，已有的直接去掉。你要的五类里，「已存在」「新术语」可以直接给；「疑似同义词」「疑似冲突」「不确定」要让 AI 多判断一步，会多一次 AI 调用。**建议**：做，但只放在待审核结果里，不改术语表。

还有两处**按你的规则我会这样处理**，除非你另有要求：
- **校对「保留原始字幕、生成新版本」**：每次校对前把当前字幕存一份历史版本（现在只有重新识别才存），改动记在 `fixes` 里，可以对比和恢复。
- **安全边界**：命令行只读写媒体库里登记的文件夹、软件自己的缓存和输出文件夹，以及设置里关联的 Obsidian 库；其他路径一律拒绝。不提供删除、批量移动、git 操作。

## 附：你提到的「跑到一半报错，刷新后结果又出现了」，原因找到了

这正是「合并规则在界面里」造成的。以 AI 校对为例：
- 校对是一批一批进行的，界面每收到一批改动，就立刻写进字幕并自动保存；
- 如果做到一半出错，界面提示「失败」，但前面那几批改动**已经保存了**；
- 重新打开时它们就「出现」了，而「已校对」标记却没打上。

找关键帧、画面复核也是这样。反过来，如果任务进行中界面被关掉，后台任务会继续跑完，但结果**没人接收，直接丢掉**。

第 1、2 阶段的任务层会把这个问题彻底解决：
- 每一步有明确的状态；
- 做到一半失败时，已经完成的部分要么完整保留并标明「部分完成」，要么不写入，不会出现说不清的状态；
- 结果由后台写盘，界面关了也不会丢。
